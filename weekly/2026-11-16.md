- 本週拆出：4 條線（4 份指南）
- 為什麼回溯：這四份指南在 v0.0.177 就有了，第一期只拆「新增」的指南，它們落在「修改的 106 份不回溯」裡
- 規格來源（追蹤用）：https://github.com/WICG/html-in-canvas 。四槽只依上游指南判定，這個連結用來追規格和實作進度

## 這週的對手

- **canvas內容對瀏覽器隱形**（1，新開）：`mwg:expose-canvas-content-to-browser-features`。畫在 canvas 上的內容，螢幕閱讀器、頁內搜尋、翻譯、列印都看不到。新開一組，因為既有的組都在講 DOM 內的元素被藏起來，這裡是內容根本不在 DOM 裡。
- **手工重現瀏覽器渲染**（1，新開）：`mwg:export-html-media-from-canvas`。截圖函式庫在 JS 裡重畫一次 DOM，遇到新的 CSS 排版就畫錯。新開一組，ledger 裡沒有「自己重做瀏覽器已經會做的繪製」這個形狀。
- **canvas裡手寫互動**（2，新開）：`mwg:interactive-content-in-3d-scenes`、`mwg:apply-webgl-shaders`。貼圖不是元素，點擊和選字要自己接。和「手寫焦點管理」形狀相近（瀏覽器會做的事自己重寫），但對象是 canvas 裡的命中測試，不是焦點，所以分開。兩條的槽 3 都判缺，見下。

沒有跨週累計 ≥3 條線的新組。

槽 3 判缺的兩條：3D 場景那份只說「不必再寫複雜的 raycasting 或自訂事件處理」，是工作量而不是可觀察的失敗；shader 那份完全沒提舊做法。

## 僵持中的線

四條全部僵持，卡在同一件事：

- HTML-in-Canvas：只有 Chrome 157 起支援（2026-11-03 進穩定版），ledger 的支援狀態記 `Limited`。
- 指南的支援資料過時：fallback 段落仍寫 "HTML-in-canvas is not natively supported by any major browser yet."，同一份前面又註 "HTML-in-Canvas is supported from Chrome 157."。已記進 PROMPT.md 的「已驗證的支援資料偏差」。（當天更正：原本照 fallback 那句記成 `無瀏覽器支援`）
- `mwg:export-html-media-from-canvas` 在其他瀏覽器的 fallback 是 `html2canvas`、`dom-to-image`、`snapdom`，也就是對手本身。
- 其餘三條在其他瀏覽器的 fallback 是把 HTML 用 CSS 疊在 canvas 上，或 `three-html-render` polyfill。

## 本週靈感

本週新能力 4 條，都只有 Chrome 157 起能用，可以先在自己的 Chrome 上做 demo。以下是發想，不是指南內容。

1. **Ctrl+F 找得到字的 canvas 圖表**
   圖表的座標軸標籤、資料標籤、圖例是真的 DOM 文字，畫在 canvas 裡但可以搜尋、選取、翻譯。
   用到：`mwg:expose-canvas-content-to-browser-features`（`drawElementImage()`）。
   限制：僅 Chrome 157 起；其他瀏覽器的 fallback 是把標籤用 CSS 疊在 canvas 上，位置要自己對。
   現成 demo：[pie-chart](https://wicg.github.io/html-in-canvas/Examples/pie-chart.html)、[complex-text](https://wicg.github.io/html-in-canvas/Examples/complex-text.html)。不必自己做，直接在上面試頁內搜尋和選字。

2. **「存成圖片」按鈕，輸出和畫面一模一樣**
   儀表板或排好版的卡片一鍵存成 PNG，不載入截圖函式庫。
   用到：`mwg:export-html-media-from-canvas`（`drawElementImage()` + `toBlob()`）。
   限制：僅 Chrome 157 起；其他瀏覽器退回 `html2canvas` 這類函式庫，新的 CSS 排版可能畫錯；跨來源內容不能畫進 canvas。
   小 demo：把這個 repo 主頁的一條線卡片畫進 canvas，按鈕下載成 PNG。
   現成 demo：無，WICG 範例沒有示範匯出。這個要自己做。

3. **把一段網頁互動錄成影片**
   操作教學、bug 重現：HTML 區塊畫進 canvas，用 `captureStream()` 接 `MediaRecorder`。
   用到：`mwg:export-html-media-from-canvas`。
   限制：同上；fallback 是用 `rrweb` 錄 DOM 變動，得到的是可重播的紀錄而不是影片檔。
   小 demo：錄下填完一張三欄表單的過程，輸出 WebM。
   現成 demo：無，WICG 範例沒有示範匯出。這個要自己做。

4. **3D 產品展示裡的真表單**
   3D 場景中的螢幕或看板貼的是真的 HTML：可以打字、選字、用鍵盤聚焦。
   用到：`mwg:interactive-content-in-3d-scenes`（Three.js `HTMLTexture` + `InteractionManager`）。
   限制：僅 Chrome 157 起；其他瀏覽器 HTML 只能平貼在 canvas 上方，不會跟著 3D 物件轉。
   現成 demo：[webGL](https://wicg.github.io/html-in-canvas/Examples/webGL.html)（HTML 貼在 3D 卡片上），README 另有 three.js 版。不必自己做。

5. **會起漣漪的真按鈕**
   按鈕和輸入框套 fragment shader（漣漪、玻璃折射、掃描線），仍然是可及的原生控制項。
   用到：`mwg:apply-webgl-shaders`（`texElementSubImage2D()` + `updateElementGeometry()`）。
   限制：僅 Chrome 157 起；其他瀏覽器完全沒有 shader 效果，只剩一般的按鈕。
   現成 demo：[webgpu-jelly-slider](https://wicg.github.io/html-in-canvas/Examples/webgpu-jelly-slider/)（果凍效果的滑桿）。它走 WebGPU；要驗證指南的 WebGL shader 路徑才需要自己做。

WICG 的範例頁（https://github.com/WICG/html-in-canvas 的 Demos 一節）共五個，上面沒列到的是 [nested-sparkles](https://wicg.github.io/html-in-canvas/Examples/nested-sparkles.html)（巢狀 `drawable` 元素）。這些連結是 2026-11-16 從 README 抄來的，還沒有逐一在 Chrome 157 上實測。

### 本 repo 的模組 demo

WICG 的範例各示範一個 API，沒有「一個功能模組怎麼用它」的例子，所以在這裡做了一個：[對手組戰報圖](../demos/ledger-chart/)（`docs/demos/ledger-chart/`）。

- 做了什麼：用 `ledger.csv` 畫每個對手組有幾條線、戰報如何。長條是 canvas 畫的，標籤是 `<button drawable>`，用 `drawElementImage()` 畫進去。
- 涵蓋點子 1、2、3：標籤可以頁內搜尋、選字、用 Tab 走訪；「下載 PNG」用 `toBlob()`，「錄 5 秒影片」用 `captureStream()`，輸出都含標籤文字。
- 順便用到 `mwg:drag-and-drop` 的做法：切換排序時用 `moveBefore()` 搬真節點，Tab 順序跟著畫面順序走。
- fallback：不支援的瀏覽器把同一批標籤用 CSS 疊在 canvas 上，搜尋和鍵盤照常，但匯出的圖和影片沒有標籤文字。這正是匯出那條線的對手。
- 2026-11-16 在 Chrome 157 上跑過：滑鼠點擊命中標籤、排序後 Tab 順序正確、PNG 裡有標籤文字、錄影能下載。fallback 分支和其他瀏覽器沒有實測。

## 糾錯備忘

本週沒有糾錯類的線。四份指南共通的一點沒有另外拆線：canvas 的格線要用 `ResizeObserver` 對齊裝置像素，否則會模糊（原文只有 "to prevent blurriness" 一句）。
