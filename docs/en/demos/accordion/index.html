Animated accordion with ::details-content

A native <details> gets an open and close height animation from a few lines of CSS. Collapsed content isn't display: none, so find-in-page still finds it and opens the item on a match.

Try it: collapse everything, then press Ctrl+F (⌘F on a Mac) and search for “hidden answer”.

What does this repo do?

It breaks new modern-web-guidance guides into problem lines: action, opponent, fallback, and unlock.

What's the difference between a new capability and a correction?

A new capability makes something newly possible; a correction uses a long-available technique and just fixes a common mistake.

Can I find collapsed content?

Yes. This is the hidden answer: the browser hides it with content-visibility, and find-in-page opens it automatically on a match.

How it works

details::details-content {
  interpolate-size: allow-keywords;
  overflow: clip;
  transition: block-size, content-visibility, display;
  transition-duration: .3s;
  transition-behavior: allow-discrete;
}
details:not([open])::details-content { block-size: 0; }

::details-content is the part of a details element that opens and closes. It used to be impossible to select, so animating it meant replacing details with a custom component and losing its native keyboard behavior and find-in-page along the way.

Without support

  • Browsers without interpolate-size open and close normally, just without the animation.
  • When the system asks for reduced motion, items open and close instantly.
  • The accordion itself is a native element and works in every browser.
