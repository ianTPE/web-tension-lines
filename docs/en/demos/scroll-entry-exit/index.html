Scroll entry and exit with view()

Scroll inside the box below. Cards grow in as they enter and shrink away as they leave. The animation's progress is tied directly to each card's position in the scroll area: it plays as far as you scroll, and runs backwards when you scroll back.

How it works

@keyframes rise-and-fade {
  entry 0%            { opacity: 0; scale: .85; }
  entry 100%, exit 0% { opacity: 1; scale: 1; }
  exit 100%           { opacity: 0; scale: .92; }
}
.card {
  animation: rise-and-fade auto linear both;
  animation-timeline: view();
}

view() creates a timeline that follows how visible this element is in its scroll area; entry and exit are the stretches where it comes in and goes out. Previously this took an IntersectionObserver or a scroll listener, computing on the main thread on every scroll.

Without support

  • A script uses IntersectionObserver to scale cards by how visible they are. The effect is close, but it runs on the main thread.
  • When the system asks for reduced motion, the cards stay still.
