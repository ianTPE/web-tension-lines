用 CSS 視覺截斷取代在 script 裡砍字串 糾錯勝Widely 單行文字溢出 · 截字傷可及性
誰在做
開發者（或寫程式的代理）
動作＋對象
單行標籤（分頁、表格格、檔名）過長時，用 text-overflow: ellipsis 或 mask 淡出只在畫面上截斷，全文留在 DOM
被什麼擋
在 script 裡把字串切短後，螢幕閱讀器、頁內搜尋、複製拿到的都是殘缺文字（引用："Screen readers announce the full text, find-in-page matches it, and copying copies it. This is why the string must never be cut in script."）
戰報
勝——截斷只發生在繪製層，輔助技術、搜尋、複製都還拿得到全文；省略號與 mask 都是 Widely available（官方宣稱）

常見寫法是在渲染前把字串截到 N 個字再加「…」，結果全文從 DOM 消失。指南要求截斷只做在視覺上；要保留副檔名這類尾巴時，在 markup 裡分段包起來，而不是切字元。另一個坑是用單一漸層當 mask：它會連焦點外框一起遮掉（"it also hides the element's focus outline"）。

支援 Masks：Widely（2023-12-07）；Container queries (size)：Widely（2023-02-14）

解鎖・發想被截斷的長標籤（檔名、分頁名）可以用純 CSS 在 hover 或 focus 時捲動顯示全文，不必寫 JS 量寬度、也不必用 title
誰在做
開發者（或寫程式的代理）
動作＋對象
用 :hover 與 :focus-visible 觸發文字捲動顯示，並以 scroll-driven animations 控制淡出與提示
被什麼擋

解鎖・發想可以把正在播放的影片、iframe 小工具、輸入到一半的表單整塊搬到別的位置而狀態不重置。以前一搬就重新載入，所以「可重排的即時儀表板」做起來很痛
誰在做
開發者（或寫程式的代理）
動作＋對象
拖放結束時用 container.moveBefore(item, ref) 一次搬動既有節點，讓視覺、鍵盤、閱讀順序一致
被什麼擋

搬既有節點排序，不用 innerHTML 重建 新能力部分改善Limited 使用者觸發的動態排序 · 重建DOM丟狀態
解鎖・發想排序或篩選後清單用 view transition 動畫「走」到新位置，項目內的捲動、焦點、播放狀態都還在。適合項目本身很重的清單（內嵌預覽、影片卡片）
誰在做
開發者（或寫程式的代理）
動作＋對象

被什麼擋

用 ::details-content 收合，保留頁內搜尋與動畫 新能力部分改善Newly 手風琴（Accordion） · 隱藏或停用把人擋在外面

誰在做
開發者（或寫程式的代理）
動作＋對象
收合內容放在 ::details-content，以 content-visibility: hidden 隱藏而非 display: none
被什麼擋
用 display: none 隱藏收合內容，頁內搜尋找不到、高度也無法動畫（引用："While closed it is hidden with content-visibility: hidden, not display: none, which is what keeps it findable and lets its size animate."）
