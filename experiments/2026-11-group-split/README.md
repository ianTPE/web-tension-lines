# 2026-11 拆分「新功能的副作用」

「新功能的副作用」有 85 條，是第二大組的兩倍多；其中 80 條是糾錯，內容都是新功能本身的使用陷阱，但踩坑的機制各不相同。這個組太籠統，任何依對手組做的統計或視覺化都會被它扭曲。

## 做法

- `rules.md`：先歸進現有的組，對不上才用候選新組，再對不上才提出新組，不准歸回原組。
- Kimi、agy 各自獨立判 85 條（`kimi.jsonl`、`agy.jsonl`），彼此看不到答案。
- 先統一兩邊意思相同的新組名（`merged.json`），再把 21 條不一致交給 Opus 匿名仲裁（`adjudicate.py` → `adjudication.json`），最終結果在 `final.json`。

## 結果

- 兩邊一致 62／85（73%）；仲裁時 Opus 支持 agy 15 條、Kimi 6 條。
- 85 條分到 23 個組，最大的「新屬性的隱藏前提」16 條。其中 11 個是新組：

| 新組 | 條數 | 形狀 |
|---|---|---|
| 新屬性的隱藏前提 | 16 | 沒報錯，但在某些條件下被靜默忽略或效果不如預期 |
| 參數或格式用錯就丟例外 | 13 | API 的參數、格式、配額不對就拋錯 |
| 轉場被跳過或錯亂 | 8 | view transition 因命名、範圍、快照出問題 |
| 沒防護不支援的瀏覽器 | 6 | 不支援的瀏覽器忽略新屬性，沒偵測也沒退路，功能悄悄壞掉 |
| 事件不冒泡收不到 | 4 | 新事件不冒泡，事件委派失效 |
| 只改外觀沒改語意或焦點 | 4 | 畫面變了，無障礙樹或焦點沒跟上 |
| 彈出層互相干擾 | 4 | popover、dialog、選單互相關掉或搶 Esc |
| 瀏覽器實作有缺陷 | 3 | 瀏覽器 bug，需要針對性繞路 |
| 兩套機制重複作用 | 2 | 同一件事用兩種機制宣告，重複觸發 |
| 相對網址解析基準錯 | 1 | 相對網址相對於錯的檔案解析 |
| 邏輯方向與實體方向脫鉤 | 1 | 一部分跟書寫方向、一部分用實體方向 |

其餘 12 條歸進現有的組，例如「不認得的語法讓整條規則失效」6 條、「優化用過頭反傷」4 條。
